# CLAUDE.md — chanpark-harness plugin

Guidance for Claude Code when working **on this plugin repository**. (For how the plugin
behaves once installed, the skills and agents themselves are the source of truth.)

## What this repo is

A Claude Code plugin merging **claude-code-harness** (base, wins on conflict) and selected
**oh-my-claudecode** agents/skills (gap-fillers), rebranded to `chanpark-harness`,
localized to English, and modernized to the current plugin spec. It is a single-plugin
marketplace (`.claude-plugin/marketplace.json`, plugin `source: "./"`).

Portability rule: **everything must work from a plain `git` checkout — no Node/Go build.**
The only compiled artifact is the committed harness Go binary in `bin/`.

## Canonical workflow (what the plugin promotes)

Plan → Work → Review, tracked in a root `Plans.md` with English status markers
**`cc:todo` / `cc:wip` / `cc:blocked`** (active) and **`cc:done` / `cc:dropped`**
(terminal), plus PM markers `pm:requested` / `pm:approved`. Active work lives in
`Plans.md`; unscheduled capture in `Plans-backlog.md`; terminal rows retire to
`.claude/memory/archive/`. Skills: `harness-plan`, `harness-work`, `harness-review`,
`harness-sync`.
The ported OMC agents are read-only/consult helpers for the gaps (architecture, requirements,
debugging, security, docs, tests, search, git, writing, interactive QA).

### Three-file layout

| File | Read by counters? | Holds |
|------|-------------------|-------|
| `Plans.md` | **yes** | Active rows (`cc:todo`/`cc:wip`/`cc:blocked`) + terminal rows not yet archived |
| `Plans-backlog.md` | **no** | Unscheduled capture. Plain bullets, **zero `cc:` markers**, no cap. Four exits: promote / decline / duplicate / snooze |
| `.claude/memory/archive/Plans-<date>.md` | **no** | Terminal rows after the sweep, plus declined backlog bullets in bulk |

Separation is by **file boundary**, not by section heading. A heading is not a filter —
every parser scans the whole file, so a `## Backlog` section would land straight in the
counts, the denominator and the HUD. That is the v1.3.6 bug one level up. The backlog
carrying no markers at all is the second layer: a counter pointed at it by mistake still
returns zero. Never introduce a `cc:backlog` state.

Budgets live in `harness.toml [plans]`. Two of them, bounding different things:
**rows** — 25 active soft, 30 hard, `cc:wip` ≤ 1; overflow routes to the backlog
(recoverable), never to unbounded growth. **Length** — `max_lines = 80` over the whole
file, boilerplate included, because the row caps count active rows only and therefore
cannot see terminal rows or boilerplate at all (measured: 30 rows = 93 lines under the
old layout, with nothing complaining). Length overflow is **reported, never refused**;
the long-form legend was moved to `skills/harness-plan/references/plans-format.md` so a
full 30-row plan still fits in 80 lines. Reported by `session-monitor.sh` at session
start **and by `plans-watcher.sh` on every write** — the latter is the only budget
surface that fires in headless `-p` mode.

`scripts/plans-sweep.sh` proposes T1 (stale rows, default **on** — see `harness.toml`
for why it ships on a bound rather than on evidence), T2 (**per-row**
archive candidates, default **on**) and T3 (backlog capture-date staleness, default
**on**), and **never writes** — a markdown file has no activity feed and no undo, so a
silent rewrite is invisible until someone reads a diff.

**T2 is per row, never per file.** It once required the entire file to be terminal,
which let one never-finished `cc:todo` block archiving of everything around it forever
(reproduced at 120 done rows / 125 lines with the sweep reporting "no candidates").
Linear's cited rule is per issue. Pinned by `plans-archive-per-row`.

`scripts/plans-dupe-check.sh "<desc>"` is the executable duplicate check: Jaccard ≥ 0.4
over `Plans.md` rows **and** live backlog bullets, called by `harness-plan` at `add`
step 2. Advisory — exit 1 means "candidates found", never an error.

### Marker counting

A marker counts as a task **only when it is the status cell of a table row** — the last
non-empty cell. Prose, the marker legend, fenced examples, HTML comments and a description
cell quoting a marker are all ignored. `scripts/lib/plans-markers.awk` is the canonical
implementation and **every consumer reads it through `scripts/lib/plans-counts.sh`**;
`hud/statusline.sh`, `scripts/hook-handlers/plans-watcher.sh`,
`scripts/hook-handlers/session-monitor.sh`, `scripts/hook-handlers/wip-guard.sh` and
`scripts/progress-snapshot.sh` all follow the same rule, and `check-regression-guard.sh`
pins it with eleven `plans-*` / `wip-guard-*` cases.

**Closed vocabulary — five `cc:` markers.** `cc:todo` / `cc:wip` / `cc:blocked` are
active; `cc:done` / `cc:dropped` are **terminal**. Both terminal states stay in the
denominator and count toward progress:
`progress = (done + dropped) / (todo + wip + blocked + done + dropped)`. Dropped counting
as progress is load-bearing, not a rounding choice: if retiring work lowered the
percentage, nothing would ever be retired and the file would grow until unread. Finer
distinctions go in the description cell, never into a new marker.

**Matching is word-bounded, not prefix-based.** `cc:wip-paused` is *not* `cc:wip` — under
the old prefix rule it was, and because wip-guard shares the vocabulary a single such row
made the Stop hook block forever. A status cell that looks like a marker but matches
nothing known is counted as `unknown` and surfaced; it used to vanish from every bucket
*and* from the denominator, which is worse.

**Status cells may never contain an HTML entity.** Commit `598f4a11` escaped `cc:` to
`cc&#58;` line-wide while neutralising markers quoted in description cells, and hit four
status cells too — they render normally and count as nothing, so a 20-row all-done ledger
reported 16. Description-cell escapes are intentional; the fix belongs in the escaping
step, never in the counter (decoding `&#58;` would also decode the deliberately-escaped
legend). Pinned by `check_plans_status_cell_entity`.

**Counter output is labelled, not positional** (`todo=N wip=N …`). The old six-bare-integer
format was read positionally, so adding a state would have shifted every field and made
`plans-watcher.sh` write `"0 0"` into a JSON number.

The binary's own `hook plans-watcher` counted markers as unanchored substrings, so one
archive sentence inflated `cc_done` by 1 (v1.3.6). There is **no Go source here** —
`bin/harness-*` is vendored from upstream and cannot be rebuilt in this repo — so the fix
took the handler over in shell. Re-vendoring a newer binary will not undo it, but do check
that `hooks.json` still points at the script; the `plans-watcher-handler` guard fails if a
`harness sync` puts the binary subcommand back. `hook session-monitor` was taken over the
same way for the same reason (`check_session_monitor_handler`). Only `hook session-init`
still prints unanchored counts and the stale six-row legend in its banner — injected
context, nothing reads it back, so it is left alone.

> **`HAR:` description prefix**: intentionally present only on the 5 canonical-loop skills
> (`harness-plan`, `harness-work`, `harness-review`, `harness-sync`, `harness-setup`).
> The auxiliary `harness-*` skills (`harness-accept`, `harness-loop`, `harness-plan-brief`,
> `harness-progress`, `harness-release`) omit the prefix by design — the split is documented
> intent, not drift.

## Invariants — do not break these

- **Plugin name `chanpark-harness`** appears in `hooks/hooks.json` root-detection grep and
  in marketplace/cache fallback paths. If you rename the plugin, update those literals too.
  The Go binary does **not** re-validate the plugin name, but `harness.toml` and the
  `.claude-code-harness.config.*` filenames are read by the binary — keep those names.
- **Status markers are English**; canonical written form is lowercase. The vocabulary is
  **closed at five** `cc:` markers — `cc:todo`/`cc:wip`/`cc:blocked` (active) and
  `cc:done`/`cc:dropped` (terminal) — plus PM markers `pm:requested`/`pm:approved`.
  Adding a sixth means changing `scripts/lib/plans-markers.awk`, the loader, both
  schemas and a regression-guard case in the SAME commit; anything less and the
  consumers disagree. `cc:cancelled`/`cc:canceled` are input aliases of `cc:dropped`
  (`dropped` is canonical because it has one spelling and cannot drift UK/US).
  **Matching precision (post-rebuild 2026-07-07)**: all binary counter paths match
  case-insensitively and count the four markers it knows; `cc:完了` and
  `pm:依頼中`/`pm:確認済`/`cursor:*` remain counted as legacy aliases. The bash scripts
  read uppercase/legacy aliases too.
- **The vendored binary will never learn `cc:dropped`** — there is no Go source here.
  Verified behaviour when it meets one: `harness doctor` and `harness validate` pass,
  `harness sync` is unaffected, and `hook session-init` simply does not count the row
  (its numbers are injected context that nothing reads back). It is a display-only
  undercount in one banner, never a wrong write. The surface that *was* armed by
  default, `hook session-monitor`, has been taken over by
  `scripts/hook-handlers/session-monitor.sh` (`check_session_monitor_handler` fails CI
  if a `harness sync` puts the binary subcommand back).
- **Agent frontmatter**: full model IDs (`claude-opus-4-8`, `claude-sonnet-5`,
  `claude-haiku-4-5`), `effort`, and `disallowedTools` (read-only consults disallow
  `Write, Edit, Agent`; others disallow `Agent`). No `permissionMode`/`mcpServers`/`hooks`
  in plugin-shipped agents (security restriction).
- **English only** for user-facing content (agents/skills/output-styles/templates); the
  grep health check enforces this for those paths. The rebuilt binaries emit English on all
  session-init/plans-watcher/monitor/TDD/CI surfaces; JP literals remain only as legacy
  marker-counting aliases and in untargeted upstream handlers (see
  `docs/patches/binary-rebuild/verification-3.3.md` V8 for the inventory).
- **`bin/harness sync` is safe post-rebuild (2026-07-07)**: it writes only
  `.claude-plugin/plugin.json` and `.claude-plugin/settings.json`, preserves unknown
  plugin.json fields (`displayName`, `defaultEnabled`), and never creates
  `.claude-plugin/hooks.json`. It OWNS and regenerates name/version/description/author/
  homepage/repository/license/keywords/skills/outputStyles from `harness.toml [project]` —
  keep that section aligned with the curated plugin.json.
- Keep `bin/harness-*` executable (mode 0755) and marked binary in `.gitattributes`.

## Health checks

```bash
CLAUDE_PLUGIN_ROOT="$PWD" ./bin/harness doctor      # config + hooks + manifest sanity
CLAUDE_PLUGIN_ROOT="$PWD" ./bin/harness validate    # validate all SKILL.md files
grep -rlP '[\x{3040}-\x{30ff}\x{4e00}-\x{9fff}]' agents skills output-styles templates  # must be empty
```

> **`harness doctor` PATH note**: the `[OK] bin/harness in PATH` line resolves to the
> **installed plugin cache copy** (e.g. `~/.claude/plugins/cache/.../bin/harness`), not
> the binary in this repo under test. This is a `$PATH` check, not a repo-integrity check;
> both the repo binary and the installed binary are expected to differ in path. Do not
> report this as drift.
